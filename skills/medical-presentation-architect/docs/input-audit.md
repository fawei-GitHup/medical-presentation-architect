# 用户输入材料审计如何影响设计

源对话提供了三版同主题口腔数字化修复演示文稿及两份 Python 生成脚本。原始文件、页面图像、科室/厂商品牌和临床内容均属于私人输入，不放入本仓库与 ZIP。下表记录由审计提炼出的工程问题；它不是新的临床指导。

| 输入审计观察 | 对 Skill 与工具的响应 |
|---|---|
| 旧脚本依赖 shape 索引、复制页面后替换文字，版式表达受到旧幻灯片框架限制 | 建立 `slide-plan.json` 与 `visual-plan.json` 中间层；按每页教学目的选择表达方式，构建器显式支持范围内的原生视觉组件，未知组件失败并说明，不假称通用模板导入 |
| 页面文字、备注、隐藏层和实际可见结果未必相同；背景/图片填充也可能遮盖底层内容 | `pptx_inspect.py` 分层清点；`pptx_lint.py` 检查隐藏页/对象、后置图片或图片填充遮字线索；逐页回渲染并要求真人审图 |
| 三个版本间有精确重复页面，某些连续页面采用重复双栏文字布局 | `visual_similarity.py` 找重复页面； QA 对重复布局和素材复用发出需解释的警告，而不是强制页面都用不同布局 |
| 部分数字、产品流程/名称、操作参数和临床建议在源稿中需进一步核证 | 源稿内容只记为 `observed`；证据账本逐项核实，暂缺的数字/指南/器械声明不能通过最终门禁。规则禁止把审计线索转写成治疗建议 |
| 既有备注有重复或与修改后页面不匹配的风险 | speaker notes 和幻灯片使用稳定 ID 绑定；审查表逐页核 notes、来源及修改一致性 |
| 页面档案包含疑似身份或日期字段 | 访谈显式询问隐私与分发边界；病例资产记录同意/去标识化状态；未清理资产不能导出 |

详细的 F01–F16→规则/脚本/测试映射见 [审计规则映射](audit-integration.md)。自动检查只给出结构与可见性线索，不能替代 OCR、医学判断、版权确认或隐私审批。示例项目全部合成，未复制源幻灯片的临床值、患者图、品牌或图文。
